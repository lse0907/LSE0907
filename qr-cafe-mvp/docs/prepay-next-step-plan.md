# 선결재 기능 다음 단계 실행계획 (코드 작업 전 확정본 v1)

> 목적: 초보 운영자/초보 개발자도 바로 실행할 수 있도록,
> "지금 당장 해야 할 일"을 순서대로 정리한 실무 체크리스트입니다.

---

## 1) 이번 주에 확정할 항목 (의사결정)

1. 요금 정책 문구 확정
   - 기본 8,900원(초기 혜택) / 정식 13,900원
   - 선결재 옵션 5,000원
2. 무료체험 30일 종료 후 상태 전환 규칙 확정
3. 선결재 활성화 3조건 확정
   - 기본 구독 active
   - 옵션 active
   - PG 연결 검증 완료
4. 파일럿(친구 카페) 성공 기준 확정
   - 실결제 1건 + 즉시 전체취소 1건 + 관리자 로그 확인

---

## 2) 관리자 화면에 먼저 넣을 기능 (코드 1차 범위)

### A. 결제/구독 상태 카드
- 기본 구독 상태: `trialing | active | past_due`
- 선결재 옵션 상태: `inactive | active | past_due`
- 무료체험 종료일 표시

### B. 테스트용 수동 승인 토글
- 기본 구독 "테스트 승인"
- 선결재 옵션 "테스트 승인"
- 주의 문구: "정식 과금 연동 전 임시 운영 모드"

### C. PG 연결 섹션
- 토스페이먼츠 가입 안내 문구
- 가맹점 가입/키 확인 링크 버튼(운영팀 URL 확정 후 반영)
- MID/Client Key/Secret Key 입력
- 저장 후 키 마스킹 표시

---

## 3) 데이터 저장 최소 구조 (1차)

### `store_billing`
- `store_id`
- `trial_end_at`
- `base_plan_status`
- `base_price_krw`
- `price_version` (`legacy` | `standard`)

### `store_addons`
- `store_id`
- `prepay_addon_status`
- `prepay_addon_price_krw` (=5000)

### `store_pg_config`
- `store_id`
- `mid`
- `client_key_masked`
- `secret_key_encrypted`
- `pg_verified_at`

---

## 4) 사용자(사장님) 화면 노출 규칙

1. 무료체험 중
   - "선결재 옵션 미리 준비" 안내 노출
   - 실제 선결재 사용 버튼은 비활성
2. 유료 전환 후
   - 기본+옵션+PG검증 완료 시 활성화
   - 미충족 항목이 있으면 부족한 조건을 문구로 안내

---

## 5) 파일럿 운영 체크리스트 (친구 카페)

1. 매장 계정 생성
2. 기본/옵션 테스트 승인 처리
3. MID/키 입력 및 연결 확인
4. 실결제 1건
5. 즉시 전체취소 1건
6. 관리자 로그 캡처/보관

---

## 6) 정식 오픈 전 전환 체크리스트

1. 우리 사업자 등록 완료
2. 우리 과금용 PG 계약 완료
3. 기본/옵션 자동결제 테스트 통과
4. 실패 결제/환불 운영 절차 문서화
5. 고객 공지(요금/옵션 정책) 게시

---

## 7) 다음 회의에서 합의할 질문 5개

1. 초기 혜택 대상의 정확한 기준일(날짜)
2. 테스트 승인 권한(누가 클릭 가능한지)
3. 무료체험 중 옵션 신청 시 과금 시작 시점
4. 키 재발급 시 재검증 절차
5. 파일럿 종료 후 정식 오픈 목표일

---

## 8) Supabase 반영 (실테스트 직전)

- SQL Editor에 아래 파일 내용을 **전체 복붙 실행**합니다.
  - `docs/sql/supabase-billing-setup.sql`
- 실행 후 관리자 `/admin/billing`에서 저장 위치가 `Supabase(DB)`로 표시되는지 확인합니다.
- DB 저장 실패 시 화면에 `Local 시뮬레이션` 배지가 보이며, 이 상태는 운영 전 임시 모드입니다.
