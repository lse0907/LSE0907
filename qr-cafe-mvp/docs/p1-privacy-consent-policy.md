# P1-3 개인정보·약관 구현 기준

상태: **P1-3A 배포 완료 / P1-3B 자동 탈퇴 처리기 로컬 구현·검증 중**
정책 기준: `Rion_Order_통합정책_법률검토전_v5_2026-08-23`

## 이번 묶음(P1-3A)

- 고객 가입: 만 14세 이상 확인을 서버에서 강제하고 전화번호는 선택으로 둔다.
- 점주 가입: 만 19세 이상 및 사업자 대표자·위임 담당자 확인을 서버에서 강제한다.
- 점주 개인 거주지 주소는 신규 수집하지 않는다. 기존 주소 데이터는 즉시 삭제하지 않는다.
- 이용정책 동의, 개인정보 처리 안내 확인, 선택 마케팅 동의를 분리한다.
- 문서 종류·대상·버전과 동의/확인/거부 시각을 불변 이벤트로 기록한다.
- 가입 이력 저장 실패 시 신규 Auth 사용자를 정리하고 가입을 완료하지 않는다.

## 정책 문서 구조

| 문서 | 가입 시 처리 | 주요 범위 |
|---|---|---|
| 고객 이용정책 | 필수 동의 | 만 14세, 비회원 주문, 거래 주체, 고객 계정과 매장별 혜택 |
| 점주 B2B 이용정책 | 필수 동의 | 만 19세·사업자 권한, 매장 책임, 구독 및 고객정보 처리 관계 |
| 고객 가입 개인정보 안내 | 필수 확인 | 가입정보, 선택 전화번호, 처리 목적과 권리 |
| 점주 가입 개인정보 안내 | 필수 확인 | 가입자·업무용 연락처, 거주지 미수집, 사업자 확인 |
| 개인정보 처리방침 검토본 | 상시 공개 | 전체 처리영역, 보유·파기, 외부업체, 안전조치 |
| 고객/점주 마케팅 수신 안내 | 선택 동의 | 리온랩스 발송, 채널, 필수 알림 분리, 철회 |
| 점주 구독·결제·취소·환불 정책 | 점주 약관·결제 화면에서 연결 | 기간, 가격·할인, 베타, 옵션, 추천, 환불, 만료 |
| 고객 주문·포인트·쿠폰 운영정책 | 고객 약관·혜택 화면에서 연결 | 비회원 주문, 판매자, 매장별 혜택, 중지·환불 정산 |

모든 정책을 하나의 가입 체크박스에 넣지 않는다. 가입에 필요한 문서는 직접 확인·동의받고, 거래 시점에 달라질 수 있는 가격·환불·혜택 조건은 독립 문서와 해당 기능 화면에서 함께 안내한다. 내부 OPS 권한·재시도 절차와 감사 운영기준은 이용자 동의문이 아니라 내부 운영 문서로 유지한다.

## 법률 검토 전 제한

현재 `/legal/*` 문서는 확정된 운영정책을 화면과 이력 구조에 연결한 검토본이다. 법률 자문을 마친 최종 약관·개인정보 처리방침으로 간주하지 않는다. 정식 공개 전 다음을 확정하여 새 문서 버전으로 교체한다.

- 사업자 표시정보와 공식 고객지원 연락처
- 처리 목적·항목별 법적 근거와 보유기간
- 실제 외부 처리업체, 처리 위치, 위탁·제3자 제공 관계
- 약관의 책임 범위, 통지·변경·분쟁 절차
- 채널별 마케팅 동의 및 철회 방식

### P1-3B 처리 원칙

- 탈퇴 요청 후 7일은 복구 대기로 두고, 이용자가 직접 요청을 취소할 수 있게 한다.
- 탈퇴 요청 접수와 Auth 사용자 삭제를 분리한다. 진행 주문·환불, 사업자 회원의 매장 소유권,
  구독·결제, 동의 증빙과 법정 보존자료를 먼저 판정한다.
- 보유기간을 코드에 임의 확정하지 않는다. 항목별 보유기간과 법적 근거는 법률 자문 후
  `privacy_retention_rules`에 확정하며, 검토 전 항목은 자동 파기하지 않는다.
- 선택 전화번호 삭제와 마케팅 동의 철회는 즉시 처리하고 불변 이벤트를 남긴다.
- 실제 삭제·익명화는 작업 대기열에서 상태·시도 횟수·실패 원인을 기록한다. Auth 삭제는
  FK·Storage·JWT 영향 확인을 통과한 건만 마지막 단계에서 실행한다.
- 탈퇴 요청 즉시 전체 세션을 로그아웃하고 계정을 제한 상태로 둔다. 다시 로그인한 경우에는
  7일 안에 탈퇴 취소를 할 수 있는 계정·개인정보 화면만 허용한다.
- 고객 주문과 사업자 구독·결제 기록은 Auth 사용자 연결을 제거하고, 보존이 필요한 정책 동의
  증빙은 무작위 보존 식별자로 분리한다. 일반 프로필과 계정 종속 혜택은 Auth 삭제 시 파기한다.
- Toss 결제 응답은 승인·환불 확인에 필요한 결제키, 주문키, 상태, 금액, 처리시각과 거래키만
  허용 목록으로 저장한다. 구매자 연락처, 카드 상세, 영수증 URL, 자유입력 취소사유 등은 저장하지 않는다.
- 보존기간 만료 파기는 `legal_review_required=false`이고 기간이 지정된 항목만 실행한다. 만료 시
  결제키·PG 응답·가격 스냅샷·가명 연결키·동의 증빙을 제거하고, 모든 보존 항목이 끝난 계정은
  탈퇴 처리 원장의 사용자 UUID도 분리한다. 실패 횟수와 원인은 보존 보류 원장에 남긴다.
- 법률 자문 전에는 거래·결제·동의·보안 감사 항목의 보존기간을 임의로 확정하지 않는다.
  따라서 자동 파기 실행기는 준비하되 해당 규칙을 승인 상태로 바꾸기 전까지 자료를 자동 삭제하지 않는다.
- 자동 처리 Cron은 `PRIVACY_DELETION_RETRY_SECRET`과 Supabase Vault의
  `rion_order_privacy_deletion_retry_secret`이 모두 준비된 이후에만 호출된다.

5. 병합·배포 후 고객/점주 가입 최소 운영 확인
