# 선결재 B안 최종 확정본 (1페이지)

> 기준: **선결재 옵션 매장에서는 결제 성공 후 주문 생성(B안)**

---

## 1) 정책 요약 (최종)

- 후불 매장(기본 기능만 유료): 고객 화면 하단 CTA는 **`주문 접수`**
- 선결재 옵션 매장: 고객 화면 하단 CTA는 **`결제하기`**
- 선결재 옵션 매장은 **결제 성공 후에만 주문이 생성**됩니다.
- 결제 실패/취소 시 주문은 생성되지 않습니다.

---

## 2) 고객 화면 문구 확정

### A. 후불 매장
- 버튼: `주문 접수`
- 보조 문구: `결제는 매장에서 진행됩니다.`

### B. 선결재 옵션 매장
- 버튼: `결제하기`
- 보조 문구: `결제 완료 후 주문이 접수됩니다.`

### C. 결제 실패/취소
- 안내 문구: `결제가 완료되지 않아 주문이 접수되지 않았습니다.`
- 재시도 버튼: `다시 결제하기`

---

## 3) 상태 전이표 (고객)

### 후불 매장
1. 장바구니 확인
2. `주문 접수` 클릭
3. 주문 생성 (`orders.status = new`, `payment_status = not_required`)
4. 완료 페이지 이동

### 선결재 옵션 매장 (B안)
1. 장바구니 확인
2. `결제하기` 클릭
3. PG 결제창
4. 결제 성공
5. 주문 생성 (`orders.status = new`, `payment_status = paid`)
6. 완료 페이지 이동

### 선결재 옵션 매장 - 실패/취소
1. PG 결제 실패 또는 사용자 취소
2. 주문 미생성
3. 실패 안내 + 재시도

---

## 4) 상태 전이표 (직원)

### 공통
- 신규 주문이 생성되면 직원 화면에 `신규`로 표시

### 후불 매장
- `신규(new)` → `제조중(making)` → `준비완료(ready)` → `완료(done)`

### 선결재 옵션 매장 (B안)
- 주문은 **결제 완료된 건만 생성**되므로 직원 화면에서는 기본적으로 `결제완료` 주문만 보게 됨
- 제조 시작 제한 로직은 안전장치로 유지 가능(예외 데이터 방어)

---

## 5) 상태 전이표 (관리자)

### 결제/구독 화면
- 기본 구독 상태
- 선결재 옵션 상태
- PG 연결 상태
- 저장 위치 배지(`Supabase(DB)` / `Local 시뮬레이션`)

### 운영 규칙
- 선결재 옵션이 `active`이고 PG 설정이 유효한 매장만 B안 적용
- 운영 중에는 DB 저장 기준으로 상태 확인

---

## 6) 데이터 기준(최종)

- `store_addons.prepay_addon_status = active` 인 경우: 고객 CTA `결제하기`
- 결제 성공 후 주문 생성 시 `orders.payment_status = paid`
- 후불 매장 주문은 `orders.payment_status = not_required`

---

## 7) 파일럿 적용 체크리스트

1. 선결재 옵션 매장/후불 매장 각각 1곳 준비
2. 선결재 매장에서 결제 성공 시에만 주문 생성되는지 확인
3. 결제 실패/취소 시 주문 미생성 확인
4. 직원 화면에서 결제완료 주문만 제조 시작되는지 확인
5. 로그 확인(주문 생성 시점 = 결제 성공 시점)

---

## 8) 오픈 전 최종 확인

- 문구/버튼 라벨이 매장 정책과 일치하는지
- 결제 성공 콜백 실패 시 재처리 전략(중복 생성 방지) 존재 여부
- 환불/취소 프로세스 문서화 완료 여부
