# P1 OPS 개인정보 요청 처리 — 로컬 구현 / 운영 미적용

## 고정 체크리스트

1. OPS 요청 관리와 회원 결과 화면 구현·로컬 검증 (이번 묶음).
2. 사용자 화면 확인 후 미반영 변경 전체 목록·마이그레이션 순서·승인 범위 확정.
3. 별도 승인 후 백업·DB 적용·실계정 최소 검증.
4. 별도 승인 후 커밋 → 푸시/PR → 병합·배포 → 운영 최소 확인.
5. AI 도입 논의 → 법률 검토 후 최종 정책 문서 정리.

기존 운영 마이그레이션·검증은 반복하지 않는다. 상위 `../supabase/` 백업은 커밋에서 제외한다.

## 진입과 권한

- OPS 홈 → 개인정보 요청 → `/ops/privacy-requests`.
- 목록·상세·처리 모두 서버에서 `master` 또는 `support` OPS 권한 확인. `viewer`, `billing`, 일반 회원은 접근 불가.
- 상세 조회와 처리 이력을 `privacy_request_events`에 기록한다. 처리 전후 이름·연락처 값은 이력에 복제하지 않는다.
- 요청 번호만 받으며 대상 회원·서비스·요청 종류는 DB 요청 행에서 결정한다. 클라이언트가 보낸 대상 회원 ID나 OPS ID를 신뢰하지 않는다.
- API 응답은 `private, no-store`. 처리 API는 동일 Origin 요청만 허용한다.

## 실제 처리 범위와 한계

| 요청 | 이번 화면에서 직접 실행 가능한 처리 | 제외 범위 |
| --- | --- | --- |
| 열람 | 고객/사업자 프로필의 현재 이름·등록 연락처를 본인 회원 화면에 제공 | 전체 데이터 내보내기, 주문·결제·사업자 증빙 |
| 정정 | 고객 프로필 이름 또는 선택 전화번호 변경 | 사업자 인증정보, 로그인 인증, 과거 거래자료 변경 |
| 삭제 | 고객 프로필 선택 전화번호를 실제 NULL 처리 | 계정 탈퇴, 주문·결제·증빙자료, 사업자 업무용 연락처 삭제 |
| 처리정지 | 해당 서비스 마케팅 동의 철회·동의 이력 저장 | 계약·주문·결제·보안 처리 전체 정지 |

- 미지원 요청은 임의 완료하지 않는다. `검토 중` 또는 `추가 확인 필요` 상태와 구체적인 남은 절차를 안내한다. 기능 미지원 자체를 법률상 거절 사유로 취급하지 않는다.
- 실제 처리 전 검토 상태가 필요하다. 처리 후 기본값은 `일부 처리`이며, OPS가 **회원 요청 전체를 해당 처리로 충족했는지 확인한 경우에만** `완료`를 선택한다.
- 완료/처리 제한은 단순 상태 전환 API가 아니다. `완료`는 지원하는 실제 실행 성공 후에만 가능하다. 처리 제한에는 회원 안내가 필수이며 데이터는 변경하지 않는다.
- 기존 탈퇴 처리 흐름은 별도이며 이 페이지에서 탈퇴나 법정 보존자료 삭제를 실행하지 않는다.
- 요청 결과는 회원의 최근 요청 내역에서 확인한다. 이메일/SMS 발송은 이번 범위가 아니다.
- 열람용 개인정보 사본을 DB에 추가 저장하지 않는다. 인증된 본인의 현재 서비스 프로필만 회원 API에서 제공한다. 최근 요청 내역은 기존과 같이 최대 20건이다.
- 자유 입력 요청은 OPS가 범위를 확인해야 한다. 추가 자료는 기존 지원 채널로 안내하며, 증빙 업로드·회원과의 대화 기능은 이번 범위가 아니다.

## 저장·동시성

신규 마이그레이션 `20260903085755_p1_ops_privacy_requests.sql`은 기존 개인정보 권리 테이블과 미적용 다중 역할 마이그레이션 뒤에 적용한다.

- 신규 테이블 없음. `profile_access_granted` 플래그, 요청 목록/이력 인덱스, 서비스 전용 처리 RPC 추가.
- RPC는 `security invoker`, 빈 search path, 실행 권한은 `service_role`만 허용. 서버 인증 외에 DB에서 OPS 권한도 재확인한다.
- 요청 행 잠금과 `updated_at` 비교로 중복·오래된 화면 처리를 차단한다.
- 실제 개인정보 변경, 결과 저장, 처리 이력 INSERT는 단일 트랜잭션으로 처리한다.
- 서비스 탈퇴·정지 또는 계정 정리 중에는 실제 처리를 막는다.
- 새 개인정보 원본 사본이나 별도 보존기간 정책은 추가하지 않는다. 기존 요청·이력 보존/익명화 흐름을 사용한다.

## 검증과 화면 미리보기

`npm run test:p1-ops-privacy-requests`: 처리 선택지·입력검증·실제 API 핸들러의 권한/Origin/중복 오류 매핑 검사.

SQL 검증: 독립 임시 폴더에 설치한 `@electric-sql/pglite@0.3.14`를 사용한다. 저장소 의존성/잠금 파일은 변경하지 않는다.

`node scripts/check-p1-ops-privacy-requests.mjs --pglite-path=<설치 경로>/dist/index.js`

합성 테이블/데이터만 사용하는 PostgreSQL 검증이며 실제 Supabase 전체 스키마·RLS·운영 배포 검증을 대체하지 않는다. 지원 동작, 미지원 유형 차단, 권한, 오래된 요청·종결 요청 차단, 탈퇴 차단, 이력 실패 시 전체 롤백, 함수 실행 권한을 확인한다.

- OPS 미리보기: `/preview/ops-privacy` (개발 모드 전용, 운영에서는 404, 가상 데이터만 사용, API 호출 없음).
- 회원 결과 미리보기: `/account/privacy?preview=1&requests=result` (기존 로컬 미리보기 조건 내).
- 공개 개발 미리보기는 OPS 인증 경로나 API 권한을 우회하지 않는다.
- Supabase 공식 함수/권한 문서와 현재 변경 이력을 확인했다. Data API 객체의 명시적 권한 설정 강화와 관련해 본 RPC는 `anon`/`authenticated` 실행 권한을 회수하고 `service_role`에만 명시적으로 부여한다. 운영 적용 직전에는 최신 변경사항을 다시 확인한다.

## 운영 반영 전 필수 확인 (미완료)

- 신규 역할·사업자 인증·부분 탈퇴 마이그레이션과 본 마이그레이션의 실제 원격 미적용 목록 및 순서.
- 실제 Supabase 스키마에서 함수 실행 권한·RLS, 회원/OPS 실계정 흐름.
- 사업자 업무용 연락처·증빙자료 등 미지원 요청에 대한 별도 안전한 실행 절차. 수동 DB 삭제를 정상 운영 절차로 간주하지 않는다.
- 전체 미반영 묶음의 사용자 승인. 본 문서는 배포 완료 선언이 아니다.
