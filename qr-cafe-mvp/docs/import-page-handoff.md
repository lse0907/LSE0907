# 일괄 등록 페이지 개선안 및 Vercel 오류 점검 문서

## 1. 문서 목적

이 문서는 새 코덱스 채팅 또는 다른 작업자에게 현재까지 논의된 **관리자 일괄 등록 페이지(`/admin/import`) 개선 방향**과 **Vercel Preview 배포 실패 점검 방향**을 전달하기 위한 업로드용 문서입니다.

현재 작업의 핵심은 기능을 더 많이 추가하는 것이 아니라, 라이브 배포를 앞두고 사용자가 혼란 없이 초기 설정을 진행할 수 있도록 일괄 등록 화면을 단순하고 안전하게 정리하는 것입니다.

## 2. 현재 상황 요약

- 프로젝트 경로: `/workspace/LSE0907/qr-cafe-mvp`
- 대상 페이지: `/admin/import`
- 목적: CSV 기반 카테고리/메뉴 일괄 등록 UX 개선
- 배포 이슈: Vercel Preview에서 `Command "npm run build" exited with 1` 오류가 반복 발생
- 주의: Vercel 캡처에 보이는 문구는 **결과 요약**일 뿐이며, 실제 원인은 Build Logs의 상세 에러 본문을 확인해야 합니다.

현재 로컬 최신 코드 기준으로는 `npm run build`가 성공한 상태까지 확인되었습니다. 따라서 Vercel 실패는 코드 자체의 일반적인 build 실패라기보다 다음 항목을 함께 확인해야 합니다.

1. Vercel Root Directory가 `qr-cafe-mvp`로 설정되어 있는지
2. Vercel이 최신 커밋을 빌드하고 있는지
3. Vercel Build Logs의 실제 에러 본문이 무엇인지
4. Preview 환경변수 설정 차이가 있는지
5. repo root와 앱 폴더의 package/lockfile 구조 때문에 Vercel이 루트를 잘못 추론하는지

## 3. Vercel 오류 점검 기준

### 3.1 반드시 확인해야 할 로그

Vercel 화면의 아래 문구만으로는 원인을 알 수 없습니다.

```text
Command "npm run build" exited with 1
```

반드시 Vercel에서 다음 영역을 펼쳐 실제 에러 본문을 확인해야 합니다.

```text
Build Logs
Deployment Summary
```

확인해야 할 실제 에러 예시는 다음과 같습니다.

```text
Type error: ...
Module not found: ...
Error occurred prerendering page ...
Failed to compile ...
```

### 3.2 Root Directory 확인

실제 Next.js 앱은 `qr-cafe-mvp` 폴더 안에 있습니다. 따라서 Vercel 설정은 다음이 되어야 합니다.

```text
Root Directory: qr-cafe-mvp
Build Command: npm run build
Install Command: npm install
Output Directory: .next
```

repo root의 `package.json`에는 실제 앱 build script가 없습니다. 실제 build script는 `qr-cafe-mvp/package.json`에 있습니다.

### 3.3 환경변수 확인

현재 preview/CI build가 Supabase env 누락으로 즉시 실패하지 않도록 fallback이 들어가 있지만, 실제 Preview/운영 동작을 위해서는 Vercel 환경변수에 아래 값이 설정되어 있어야 합니다.

```text
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY
```

## 4. 일괄 등록 페이지 개선 목표

일괄 등록 페이지는 초기설정 마법사의 순서와 충돌하면 안 됩니다.

초기설정 흐름은 다음 순서입니다.

```text
1. 카테고리 등록
2. 옵션 설정
3. 메뉴 등록
```

따라서 일괄 등록 페이지도 사용자가 이 흐름에 맞춰 한 단계씩 진행할 수 있어야 합니다.

---

## 5. 최종 UX 방향

### 5.1 등록 대상은 2개만 노출

사용자에게 보여줄 등록 대상은 다음 두 개만 유지합니다.

```text
카테고리 등록
메뉴 등록
```

제거 또는 숨김 처리해야 할 항목:

```text
카테고리 + 메뉴 동시 등록
```

이유:

- 초기설정에서 카테고리 단계에 들어온 사용자가 메뉴 파일까지 준비해야 하는 것처럼 오해할 수 있습니다.
- 카테고리와 메뉴를 동시에 등록하는 방식은 고급 기능에 가깝고, 초기 사용자에게는 혼란을 줍니다.
- 라이브 배포/테스터 모집 단계에서는 단순한 흐름이 더 안전합니다.

### 5.2 매장 ID 직접 입력 제거

파일 업로드 영역에 매장 ID 입력 필드를 두지 않습니다.

대신 상단에 현재 선택된 매장만 표시합니다.

```text
현재 매장: 서민테스트4
```

매장이 선택되지 않은 경우에는 입력창 대신 경고를 표시합니다.

```text
관리자 홈에서 매장을 먼저 선택해 주세요.
```

이유:

- 이미 선택된 매장이 있는데 하단에서 매장 ID를 다시 수정할 수 있으면 실수로 다른 매장에 데이터를 반영할 위험이 있습니다.
- 일반 관리자에게 store_id 직접 입력은 불필요합니다.
- 라이브 환경에서는 잘못된 매장 업로드를 막는 것이 더 중요합니다.

### 5.3 상단 이동 버튼은 모바일에서도 1줄 유지

모바일 세로 화면에서 아래 버튼들이 각각 한 줄씩 3줄로 떨어지면 공간을 많이 차지합니다.

```text
관리자 홈
카테고리관리
메뉴관리
```

원하는 형태:

```text
[관리자 홈] [카테고리관리] [메뉴관리]
```

방향:

- 헤더 전용 액션 영역을 둡니다.
- 모바일에서 버튼 높이, 패딩, 글자 크기를 줄입니다.
- 일반 업로드/검증 버튼까지 작아지지 않도록 헤더 버튼에만 별도 스타일을 적용합니다.

### 5.4 템플릿 다운로드는 선택 카드 내부에 배치

기존처럼 별도 `템플릿 다운로드` 섹션을 두면 모바일에서 세로 공간이 길어집니다.

원하는 흐름:

```text
무엇을 등록할까요?

[카테고리 등록]
초기설정 순서에 맞게 categories.csv만 업로드합니다.
[카테고리 템플릿 다운로드]

[메뉴 등록]
이미 등록된 카테고리에 menus.csv를 연결합니다.
[메뉴 템플릿 다운로드]
```

추천 방식:

- 선택된 등록 카드 내부에만 템플릿 다운로드 버튼을 노출합니다.
- 별도의 템플릿 다운로드 카드/섹션은 제거합니다.

### 5.5 작성 방법과 파일 업로드 통합

기존처럼 `작성 방법`과 `파일 업로드`가 분리되면 모바일에서 흐름이 길어집니다.

원하는 섹션 제목:

```text
1. 작성 방법 및 업로드
```

한 카드 안에서 다음 흐름이 이어져야 합니다.

```text
작성 규칙 확인 → 파일 선택 → 검증 실행
```

### 5.6 검증 결과와 반영 예정은 유지

전체 흐름은 다음 3단계로 정리합니다.

```text
1. 작성 방법 및 업로드
2. 검증 결과
3. 반영 예정
```

검증 결과에서는 다음을 명확히 보여줘야 합니다.

- 검증 전 안내
- 검증 성공 상태
- 검증 실패 상태
- 오류가 발생한 파일명
- 행 번호
- 컬럼명
- 입력값
- 해결 방법

반영 전 확인 모달은 유지합니다.

## 8. CSV 검증 규칙

### 8.1 카테고리 CSV

파일명 예시:

```text
categories.csv
```

필수 컬럼:

```text
category_name
```

선택 컬럼:

```text
sort_order
is_active
```

검증 규칙:

1. `category_name`은 필수입니다.
2. 같은 파일 안에서 같은 카테고리명이 중복되면 안 됩니다.
3. `sort_order`는 1 이상의 정수만 허용합니다.
4. `is_active`는 `Y`, `N`, `TRUE`, `FALSE`, `1`, `0`을 허용합니다.
5. `is_active`를 비우면 기본값은 사용 상태입니다.
6. 첫 줄의 영문 컬럼명은 수정하면 안 됩니다.

### 8.2 메뉴 CSV

파일명 예시:

```text
menus.csv
```

필수 컬럼:

```text
menu_name
price
category_name
```

선택 컬럼:

```text
is_sold_out
```

검증 규칙:

1. `menu_name`은 필수입니다.
2. `price`는 필수이며 숫자만 허용합니다.
3. `category_name`은 현재 매장에 등록된 카테고리명과 정확히 같아야 합니다.
4. 현재 등록된 카테고리가 없으면 메뉴 업로드를 진행할 수 없습니다.
5. `is_sold_out`은 `Y`, `N`, `TRUE`, `FALSE`, `1`, `0`을 허용합니다.
6. 오류는 행 번호, 컬럼명, 입력값, 해결 방법을 함께 보여줘야 합니다.

## 9. 디자인 기준

### 9.1 색상

```text
기본 카드: 흰색 배경 + 연한 회색 테두리
선택 카드: 연한 파란 배경 + 파란 테두리 + 약한 파란 shadow
안내 박스: 연노랑 배경 + 노랑 테두리
성공 상태: 연녹색 배경 + 녹색 텍스트
오류 상태: 연빨강 배경 + 빨강 텍스트
경고 상태: 연노랑 배경 + 갈색 텍스트
```

### 9.2 버튼 우선순위

```text
템플릿 다운로드: 보조 버튼
검증 실행: Primary 버튼
검증 통과 데이터 반영: Primary 버튼
관리자 홈/카테고리/메뉴 이동: 상단 compact 버튼
```

## 10. 새 작업자에게 요청할 작업

새 작업자는 다음 순서로 진행해야 합니다.

### 10.1 Vercel 오류 확인

1. Vercel Build Logs의 상세 에러 본문을 확인합니다.
2. Root Directory가 `qr-cafe-mvp`인지 확인합니다.
3. Vercel이 최신 커밋을 빌드하는지 확인합니다.
4. Vercel Preview 환경변수를 확인합니다.
5. 로컬 `npm run build`와 Vercel build 차이를 비교합니다.

### 10.2 일괄 등록 페이지 유지/정리

1. 카테고리/메뉴 2개 방식만 유지합니다.
2. 카테고리+메뉴 동시 등록은 사용자에게 노출하지 않습니다.
3. 템플릿 다운로드는 선택 카드 내부에 둡니다.
4. 매장 ID 직접 입력은 제거합니다.
5. 작성 방법과 파일 업로드는 하나의 카드로 합칩니다.
6. 모바일에서 상단 이동 버튼은 1줄로 유지합니다.
7. 태블릿/모바일에서 카드와 버튼 크기를 최적화합니다.
8. 검증 결과와 반영 확인 모달은 유지합니다.
