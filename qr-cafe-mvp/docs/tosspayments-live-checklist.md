# 선결재 기능(유료 옵션) 정책/운영 초안

> 이 문서는 **초보 운영자/초보 개발자도 이해할 수 있게**,
> "기본 구독"과 "선결재 기능(추가 옵션)"을 어떻게 나눠 운영할지 정리한 1차 기준입니다.

---

## 1) 우리가 하려는 방식 (한 줄 요약)

- 매장은 토스페이먼츠(PG)를 **직접 가입/심사**합니다.
- 우리는 PG 결제수수료를 받지 않고, 우리 서비스의 **구독 요금**만 받습니다.
- 선결재 기능은 기본 구독과 별개의 **유료 옵션**으로 제공합니다.

---

## 2) 요금 정책 (확정 초안)

### 공통
- 가입 후 **30일 무료체험**
- 30일 이후 기본 기능(메뉴/QR/주문 등) 유료 전환

### 기본 사용료
- 초기 정책: **월 8,900원**
- 정식 오픈 이후 신규 가입자: **월 13,900원**
- 초기 테스트/초기 가입자 혜택 대상은 "평생 기본요금 유지" 정책 적용

### 추가 유료 옵션
- 옵션 이름: **선결재 기능**
- 옵션 요금: **월 5,000원**
- 선결재 기능을 쓰려면 기본 사용료 + 옵션요금 모두 결제되어야 함

---

## 3) 선결재 기능 활성화 조건

아래 3개를 모두 만족해야 선결재 기능이 활성화됩니다.

1. 기본 기능 구독 결제 완료
2. 선결재 옵션 결제 완료
3. 매장 PG 연동 정보(MID/키) 연결 및 검증 완료

즉, 하나라도 미충족이면 선결재 기능은 OFF 상태를 유지합니다.

---

## 4) 무료체험 중 운영 방식

- 무료체험 기간에는 선결재 기능을 바로 강제하지 않고, **제안(안내) 방식**으로 노출합니다.
- 예시 문구:
  - "지금 선결재 옵션을 미리 설정해 두면, 유료 전환 후 바로 사용할 수 있어요."
- 목적:
  - 기능 이해도 상승
  - 유료 전환 시 이탈 감소

---

## 5) PG(토스페이먼츠) 연동 역할 분리

### 매장(사장님)이 하는 일
- 토스페이먼츠 가맹점 가입/심사
- 본인 매장 MID 및 라이브 키 발급

### 우리 서비스가 하는 일
- 매장 단위로 MID/키를 연결할 수 있는 관리 화면 제공
- 연결값 검증(필수값, 포맷, 연결 테스트)
- 결제 승인/취소 로그를 관리자에서 확인할 수 있게 제공

---

## 6) 사장님 안내 문구/링크(필수)

PG사를 토스페이먼츠로 고정했기 때문에, 사장님이 따라할 수 있는 안내가 반드시 필요합니다.

- 관리자 화면에 "토스페이먼츠 가입이 필요해요" 안내 박스 노출
- "가맹점 가입", "MID/키 확인 방법" 링크 버튼 제공
- 초보자용 안내 문구 예시:
  - "토스페이먼츠를 아직 사용하지 않는 매장은 먼저 가입/심사를 완료해 주세요."
  - "승인 후 발급되는 MID/라이브 키를 아래 입력하면 선결재 기능을 활성화할 수 있어요."

> 링크 URL은 실제 운영팀이 확정 후 반영합니다. (문서 단계에서는 항목만 고정)

---

## 7) 키 보안 저장 권장 방식

권장: **입력 후 마스킹 + 원문 재노출 금지**

- 화면 표시는 일부만 보이게 (예: `live_ck_****ABCD`)
- `secret key`는 저장 후 다시 원문 표시하지 않음
- 키 수정이 필요하면 "재입력" 방식 사용
- 키 변경 시점/수정자 로그 저장

이 방식은 운영 중 키 유출 위험을 크게 줄여줍니다.

---

## 8) 현재 단계(파일럿) 결제 상태 운영 원칙

현재는 서비스 판매자(우리) 사업자/정식 PG 계약 전이므로,
기본 구독 결제와 선결재 옵션 결제는 **테스트용 승인 상태(수동 승인)** 로 운영합니다.

- `기본 구독 결제 완료`: 관리자에서 테스트 승인 처리
- `선결재 옵션 결제 완료`: 관리자에서 테스트 승인 처리
- 실제 자동결제 연동은 1차 오픈 시점(사업자 등록 + PG 계약 완료 후) 전환

즉, 지금 단계 목표는 **실과금 구축**이 아니라 **기능/흐름 검증**입니다.

---

## 9) 1차 파일럿(친구 카페) 테스트 기준

### 대상
- 친구 카페 1개 매장

### 통과 기준 (필수)
1. 실결제 1건 성공
2. 방금 결제한 건 즉시 전체취소 1건 성공
3. 관리자 로그(결제/취소 기록) 확인

### 권장 추가 점검
- 같은 주문의 중복 승인 방지 확인
- 실패 시 주문 상태 롤백/에러 메시지 확인

---

## 10) 1차 운영 규모

- 초기 테스트 참여자 목표: **약 100~150명**
- 목적:
  - 실제 운영에서 결제/취소 흐름 안정성 확인
  - 요금제/옵션 안내 문구 반응 확인

---

## 11) 정식 오픈 전환 조건

아래 조건 충족 시 수동 승인 모드에서 실결제 모드로 전환합니다.

1. 우리 사업자 등록 완료
2. 우리 서비스 과금용 PG 계약/정산 체계 완료
3. 기본 구독/옵션 결제 자동 청구 테스트 완료
4. 장애 대응(환불/오류 처리) 운영 절차 문서화

---

## 12) 구현 우선순위 제안 (코드 작업 전 합의용)

1. 관리자에 결제/구독 화면(정책/상태 확인)
2. 기본 구독 상태 + 선결재 옵션 상태 분리 저장
3. PG 키 입력/마스킹/검증
4. 선결재 ON/OFF 조건 제어
5. 친구 카페 실결제/즉시취소 검증
6. 정식 오픈 시 결제 자동화 연동
