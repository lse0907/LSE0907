## 2026-10-21 · PR 최종 리뷰 보완

- Vercel 함수 요청 본문 4.5MB 제한에 맞춰 분석 입력은 JSON 직렬화·파일명·base64를 포함해 4MiB 이하로 사전 확인한다. 사진 장수 제한이 아니라 한 번에 전송하는 크기 제한이며, 큰 자료는 분석 전에 사진 크기 축소/분할 첨부를 안내한다. 서버 본문 제한도 소스 제한 + 64KiB로 함께 낮췄다. 과거의 16MiB 기록은 이전 단계 값이다.
- 근거: https://vercel.com/docs/functions/limitations#request-body-size
- 분석 API가 null/배열/문자열 JSON을 받으면 500이 아니라 400으로 거부하도록 보완했다. 두 변경 모두 외부 호출 없는 회귀 검사에 추가했다.
- PR에는 비밀 환경파일, 광고 이미지, 실제 분석 결과/화면 캡처, 원격 DB를 직접 쓰거나 정리하는 일회성 live 스크립트/rollback SQL은 포함하지 않는다. 기존 로컬 파일을 삭제하지 않는다.
- 이미 적용된 두 DB 마이그레이션을 이력과 함께 버전 관리한다. PR 생성/병합 자체로 마이그레이션을 다시 실행하거나 운영 AI를 활성화하지 않는다.

## 2026-10-21 · 정식 관리자 경로 준비 (운영 활성화하지 않음)

- 정식 API `/api/admin/menu-setup/{analyze,compatibility,register}`를 추가했다. 개발용 API와 같은 `menuSetupRoutes` 핸들러 팩터리를 사용하므로 권한/본문 상한/예약/등록 로직을 복제하지 않는다. 통합 관리자 컴포넌트는 정식 API, 개발 미리보기는 기존 API로 요청한다.
- 운영 경로는 `MENU_SETUP_ENABLED=true`, 빌드 시 `NEXT_PUBLIC_MENU_SETUP_ENABLED=true`, 유효한 `MENU_SETUP_ORIGIN=https://실제운영호스트`가 모두 있어야 열린다. 기본값은 false/빈 값이다. 서버 설정/공개 빌드 설정은 서로 대체되지 않는다.
- 운영 Origin은 명시한 HTTPS origin과 요청 URL origin이 모두 일치해야 한다. 누락/null/다른 호스트/다른 프로토콜/경로·계정정보를 넣은 Origin은 거부한다. Host/Forwarded 헤더를 허용 주소 설정으로 사용하지 않는다. 개발 환경은 기존 loopback 별칭의 같은 프로토콜·포트만 허용한다. 운영에서 개발용 API와 미리보기 페이지는 계속 차단된다.
- 분석은 기존 `AI_EXTERNAL_CALLS_ENABLED`, `MENU_SETUP_ANALYSIS_ENABLED` 및 DB 매장별 AI 등록/예산/호출 제한을 추가로 만족해야 한다. 저장은 `MENU_SETUP_REGISTRATION_ENABLED`가 별도로 필요하다. 소유자 검증·기존 매장 덮어쓰기 방지·최종 승인·동일 요청 복구·원자적 RPC는 유지했다.
- 초기설정/메뉴/카테고리/옵션의 사진·파일 진입 문구는 공개 빌드 플래그가 켜진 경우에만 운영 UI에 표시한다. 플래그가 꺼져 있으면 기존 CSV 진입을 유지한다. 공개 플래그만 켜고 서버 조건이 충족되지 않으면 정식 페이지/API가 차단되므로 반드시 함께 설정해야 한다.
- `check-menu-setup-rollout.cjs` 추가: 기본 비활성, 잘못된 배포 주소, 개발용 API의 운영 차단, 악성/누락 Origin, Forwarded 헤더 위장, owner 거부 시 부작용 없음, 정식 3개 API 정상 경로, 기존 매장 호환 검사, 분석/저장 개별 비활성화를 오프라인 검증했다.
- 회귀 검사 9종, TypeScript, 새 API/보안 모듈과 신규 테스트 ESLint 및 diff 공백 검사 통과. Next 운영 빌드도 통과했다. Windows 격리 환경의 경로/소켓 접근 거부는 허가된 비격리 실행에서 재검증했다.
- 빌드한 production 앱을 PC의 127.0.0.1에만 띄워 실제 HTTP POST로 정식 API 3개와 개발 API 3개 모두 404 및 private/no-store를 확인했다. 점검 서버는 종료했다. 활성 상태의 실제 운영 도메인 HTTP 종단 검증은 아직 하지 않았다.
- 실제 로컬 비밀 환경파일/Vercel 환경변수/운영 DB/매장 한도/공개 상태는 변경하지 않았다. 새 AI 호출·검증 매장 생성·운영 배포도 하지 않았다.

다음 단계: 변경 범위 리뷰 및 PR 준비 → 병합/비활성 배포 → 대상 매장·한도·실제 HTTPS 주소를 확인한 뒤 별도 승인으로 제한적 활성화. 운영에서 처음부터 모든 매장에 열었다고 간주하지 않는다. 원본 보관/제공자 전송 안내와 현행 테이블 잠금의 운영 영향도 공개 전에 재확인한다.

- 실제 관리자 화면을 휴대폰에서 촬영→분석→수정→등록하는 전체 흐름, HEIC 등 기기별 형식, 운영 부하/광범위 테이블 잠금 성능은 이번 검증의 통과 범위가 아니다. 기존 QR 재검증은 이 추가 기능의 필수 잔여 작업으로 두지 않는다.
