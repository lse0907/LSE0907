# 고객 주문 준비 알림 계획

## 목적

포장 또는 매장 이용 고객이 주문 화면을 닫은 뒤에도 메뉴 준비 완료를 알 수 있도록 한다.
알림 수신은 고객의 명시적 선택이 있어야 하며, 주문 자체의 완료 조건이 아니다.

## 확정한 사용자 경험

1. 주문 완료 화면에서만 `메뉴 준비 알림 받기`를 제안한다.
2. 고객이 버튼을 누른 직후에만 브라우저 알림 권한을 요청한다.
3. 수신을 거절하거나 지원하지 않는 기기에서도 주문 조회와 매장 호출 번호는 계속 사용할 수 있다.
4. 메뉴 상태가 `ready_for_packing`으로 전환될 때, 해당 주문에만 준비 완료 알림을 1회 보낸다.
5. 주문이 수령 완료 또는 취소되면 해당 주문의 알림 동의를 자동 종료한다.
6. 화면에는 `휴대폰 설정, 무음 또는 집중 모드에 따라 소리·진동은 제한될 수 있습니다.`를 표시한다.

## 범위와 개인정보 원칙

- 동의 범위는 **매장 전체나 기기 전체가 아닌 한 건의 주문**이다.
- 웹 푸시 구독 주소와 암호화 키, 주문 ID, 매장 ID, 발송·해제 시각만 저장한다.
- 주문 품목, 결제 정보, 전화번호, 고객 이름을 푸시 구독 데이터에 중복 저장하지 않는다.
- 브라우저에는 직접 테이블 접근 권한을 주지 않는다. 구독·해제 API는 주문 ID와 고객 주문 확인 토큰을 서버에서 검증한다.
- 준비 완료가 아닌 주문 변경에는 발송하지 않는다. 재시도해도 같은 주문에는 중복 알림을 보내지 않는다.

## 구현 구성

### 1. 고객 화면

- 주문 완료(`/done`)에 알림 선택 카드 추가
- 브라우저·PWA·권한 지원 여부를 먼저 확인
- 지원되지 않는 환경은 기능을 숨기지 않고 `이 기기에서는 주문 조회 화면으로 안내드립니다.`라고 안내
- 고객이 해제하면 즉시 서버 구독을 비활성화

### 2. PWA

- 기존 `/sw.js`에 `push`, `notificationclick` 처리 추가
- 알림을 누르면 해당 주문의 상태 화면으로 연결
- 알림 본문에는 매장명과 주문번호만 사용하고, 메뉴·결제 정보는 포함하지 않음

### 3. 서버·DB

- 서버 전용 `customer_order_push_subscriptions` 테이블
- `store_id`, `order_id`, `endpoint`, 암호화 키, 상태, 발송 시각, 해제 시각을 기록
- 주문 상태가 `ready_for_packing`으로 확정되는 서버 경로에서만 발송 작업을 생성
- 발송 실패(구독 만료 등)는 구독을 비활성화하고 내부 이력에만 남김

### 4. 배포 설정

- VAPID 공개키: 브라우저에 제공 가능
- VAPID 개인키: Vercel 서버 환경변수에만 저장
- 서비스 워커, 실제 Android Chrome, iPhone 홈 화면 웹앱에서 각각 수동 검증

## 완료 조건

- [ ] 고객이 버튼을 누르기 전에는 권한 팝업이 뜨지 않는다.
- [ ] 한 주문의 준비 완료에 알림이 최대 1회만 전송된다.
- [ ] 취소·수령 완료 주문은 전송 대상에서 제외된다.
- [ ] 구독 해제·만료가 다음 주문에 영향을 주지 않는다.
- [ ] 주문 토큰이 없거나 틀리면 구독·해제가 거부된다.
- [ ] Android, iPhone 홈 화면 웹앱, 알림 미지원 환경에서 각각 안내가 자연스럽다.
